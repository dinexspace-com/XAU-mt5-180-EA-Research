# Research & Backtesting Methodology

## 1. Purpose

This document defines the research and validation methodology used in the
`xauusd-mt5-ea-research` repository.

The objective is to develop and evaluate XAUUSD trading strategies for
MetaTrader 5 using a reproducible process:

Research Hypothesis
        ↓
EA Implementation
        ↓
Baseline Backtest
        ↓
Result Analysis
        ↓
Controlled Modification
        ↓
Retest
        ↓
Independent Validation

A strategy is not considered successful simply because one backtest is
profitable.

Failed experiments are retained as research evidence.

---

## 2. Research Principles

### 2.1 Hypothesis Before Optimization

Each EA starts from a clearly defined trading hypothesis.

Example:

> A breakout may have a higher probability of continuation when market
> trend strength exceeds a defined ADX threshold.

The trading logic must be defined before evaluating the result.

Parameters should not be changed merely to fit historical performance.

---

### 2.2 One Major Change at a Time

When a baseline fails or requires improvement, experiments should modify
one major component at a time whenever practical.

Example:

Baseline:

Breakout + ADX

Experiment 01:

Breakout + ADX + DI Direction

Experiment 02:

Breakout + ADX + DI Direction + Rising ADX

This allows the effect of each modification to be measured.

Changing many filters simultaneously makes it difficult to determine
which change caused the result.

---

### 2.3 Preserve Negative Results

Failed backtests must not be deleted simply because they are unprofitable.

Negative results provide useful evidence about:

- invalid assumptions;
- unsuitable parameters;
- market regimes;
- excessive risk;
- weak filters;
- strategy instability.

The original baseline should remain available for comparison with later
experiments.

---

## 3. EA Implementation Requirements

Each EA should be stored separately:

EAs/
└── EA-XXX_Strategy_Name/
    ├── EA-XXX_Strategy_Name.mq5
    └── README.md

The README should document:

- strategy concept;
- entry logic;
- exit logic;
- filters;
- risk management;
- default parameters;
- platform requirements;
- known limitations.

The source code is the authoritative implementation of the strategy.

Documentation must describe the actual implemented logic rather than an
intended or hypothetical version of the strategy.

---

## 4. Baseline Backtest

Every new EA should first receive a baseline backtest using its defined
default configuration.

The purpose of the baseline is not optimization.

Its purpose is to establish a reference result against which future
experiments can be compared.

For XAUUSD research, the report should record at minimum:

- Symbol
- Timeframe
- Test period
- Initial deposit
- Leverage
- Lot size
- History quality
- Strategy parameters
- Number of trades

Whenever available, testing should use high-quality tick data.

---

## 5. Backtest Evidence

The original MetaTrader 5 Strategy Tester output should be preserved.

Recommended structure:

Backtest/
└── EA-XXX_Strategy_Name/
    ├── README.md
    ├── ReportTester.html
    ├── ReportTester.png
    ├── ReportTester-hst.png
    ├── ReportTester-mfemae.png
    └── ReportTester-holding.png

The HTML report is the primary backtest evidence.

It should not be manually edited to improve or alter reported results.

Associated charts should be retained when generated by MetaTrader 5.

---

## 6. Core Evaluation Metrics

Backtests should be evaluated using multiple metrics rather than Net
Profit alone.

### Net Profit

Total realized profit or loss over the test period.

### Profit Factor

Gross Profit / Gross Loss

A value below 1 indicates that gross losses exceed gross profits.

### Expected Payoff

Average expected profit or loss per trade.

Negative Expected Payoff indicates negative historical expectancy for
the tested configuration.

### Maximum Drawdown

Measures the largest decline during the backtest.

Drawdown must be considered together with profitability.

A profitable strategy with excessive drawdown may still be unsuitable.

### Win Rate

Percentage of profitable trades.

Win Rate must not be evaluated independently.

A lower Win Rate may still be viable when average winners are
significantly larger than average losers.

### Trade Count

The number of trades used to produce the result.

Very small samples provide weak evidence about strategy behavior.

### Average Profit / Loss

Average winning trade and average losing trade should be examined to
understand the payoff structure of the strategy.

### Sharpe Ratio

Used as an additional measure of return relative to variability.

It should not be used as the sole criterion for strategy acceptance.

---

## 7. Baseline Classification

A baseline backtest can be classified as:

### PASS

The tested configuration demonstrates positive historical expectancy
and satisfies the predefined research criteria.

### FAIL

The tested configuration fails one or more critical criteria or shows
clearly unacceptable risk/performance.

### INCONCLUSIVE

The available evidence is insufficient to reach a useful conclusion.

Examples include:

- insufficient trades;
- insufficient test period;
- questionable data quality;
- execution errors;
- incomplete report.

PASS does not mean production-ready.

It only means the experiment passed its current research stage.

---

## 8. Strategy Iteration

When a baseline fails, the next experiment should begin with a specific
reason for the modification.

Example:

Observation:

ADX confirms trend strength but does not independently determine
direction.

Hypothesis:

Adding directional confirmation may reduce low-quality breakout entries.

Modification:

BUY:
Breakout
AND ADX > Threshold
AND +DI > -DI

SELL:
Breakout
AND ADX > Threshold
AND -DI > +DI

Then backtest the modified strategy while keeping other major variables
unchanged.

---

## 9. Parameter Optimization

Optimization should only begin after the basic strategy logic has been
tested.

The objective of optimization is to study parameter sensitivity, not to
search blindly for the highest historical profit.

Examples of parameters that may be tested:

- Breakout Lookback
- Breakout Buffer
- ADX Period
- ADX Threshold
- Stop Loss
- Take Profit
- Break Even
- Trailing Stop

Optimization results must not replace the original baseline.

---

## 10. Overfitting Control

A strategy that performs well on the same data used to develop it may
be overfitted.

Therefore development data and validation data should be separated.

Recommended workflow:

In-Sample
    ↓
Develop / modify strategy
    ↓
Out-of-Sample
    ↓
Validate unseen historical period
    ↓
Forward Test
    ↓
Evaluate live-like behavior

Parameters selected using one historical period should be tested on a
different period without further adjustment.

---

## 11. Multi-Timeframe Validation

A strategy initially developed on one timeframe may later be tested on
additional timeframes.

For example:

- M1
- M5
- M15

The objective is not to automatically choose whichever timeframe
produces the highest historical profit.

The purpose is to investigate whether the underlying strategy remains
stable under different levels of market noise.

Each timeframe test should be recorded separately.

---

## 12. Execution Assumptions

Backtest results depend on trading conditions.

Important variables include:

- spread;
- slippage;
- commission;
- symbol specification;
- broker execution;
- minimum stop distance;
- tick data;
- leverage.

These conditions should be preserved in the Strategy Tester report
whenever possible.

Results from one broker or symbol specification should not automatically
be assumed to reproduce identically elsewhere.

---

## 13. Risk Management

Risk management must be evaluated separately from signal quality.

A strategy should not be made to appear profitable merely by increasing
lot size or leverage.

Research should distinguish between:

Signal Edge

and

Position Sizing / Risk Management

Fixed-lot testing may be used for baseline comparison because it makes
different strategy variants easier to compare.

Risk-based position sizing can be evaluated after the underlying signal
shows sufficient evidence.

---

## 14. Validation Stages

The research process follows these stages:

### Stage 1 — Strategy Definition

Define the trading hypothesis and rules.

### Stage 2 — Implementation

Convert the rules into an MQL5 Expert Advisor.

### Stage 3 — Baseline Backtest

Test the original configuration.

### Stage 4 — Analysis

Identify weaknesses using backtest evidence.

### Stage 5 — Controlled Experiments

Modify one major hypothesis at a time.

### Stage 6 — Out-of-Sample Validation

Test promising configurations on unseen historical data.

### Stage 7 — Forward Testing

Run the strategy under live-like market conditions without risking
production capital where practical.

### Stage 8 — Production Assessment

Only after the previous stages should the strategy be considered for
possible production use.

---

## 15. Reproducibility

Every reported result should be traceable to:

Strategy Source
    +
Strategy Parameters
    +
Test Environment
    +
MT5 Strategy Tester Report

Another researcher should be able to identify:

1. Which EA version was tested.
2. Which parameters were used.
3. Which symbol and timeframe were used.
4. Which historical period was tested.
5. What the resulting performance was.

If these cannot be determined, the experiment should not be considered
fully reproducible.

## 18. Core Rule

Research results must follow the evidence.

A profitable backtest is not proof of future profitability.

A failed backtest is not discarded.

Every meaningful experiment should leave behind:

Code
+
Configuration
+
Backtest
+
Evidence
+
Conclusion
